1. Full end-to-end flow - single walkthrough diagram

One diagram covering scrape, enrich decisions, all 7 AI nodes, food_intel save, APIs, UI live vs dummy, and what comes from where.

Shape legend:
  • Cylinder = database / storage (Postgres, S3, food_intel)
  • Parallelogram = input/output (scrapers, APIs, URLs)
  • Rectangle = process step
  • Rounded / subroutine = CLI entry or assemble step
  • Diamond = decision
  • Hexagon = AI node
  • Pill / circle = UI screen or start/end
Walkthrough order:
  • 1 Scrape: external writers fill public Postgres tables and upload JPGs to S3.
  • 2 Enrich CLI: fetch brand posts, normalize, map brand, skip if done, resolve/presign image.
  • 3 LangGraph: 5 text nodes from caption + 2 vision nodes from image, then assemble.
  • 4 Save: food_intel.post_analysis JSONB plus theme/product facet tables and brand_profile.
  • 5 APIs: Brand endpoints live; visual gallery planned; some visual brand endpoints not wired in UI.
  • 6 UI: Brand Intelligence partially live; Trends / Visual / Persona / Overview still dummy.
  • 7 Sources: scraped vs AI text vs AI vision vs derived SQL facets.

2. Image lifecycle - when stored, when loaded

Images exist before AI runs. Vision nodes load them only during enrichment (and later gallery APIs).

flowchart TB
  A1[/1. Scraper writes post row/]
  A2[/1. Scraper uploads JPG to S3/]
  B1[(2. Postgres public\nposts + profiles)]
  B2[(2. S3 raw media)]
  C1[3. Read post from Postgres]
  C2[3. Resolve image_ref from S3]
  C3{{3. AI text + vision analysis}}
  C4[(3. Save analysis to food_intel)]
  D1[/4. Brand / Visual APIs/]
  D2([4. UI dashboards])
  A1 --> B1 --> C1
  A2 --> B2 --> C2
  C1 --> C3
  C2 --> C3
  C3 --> C4 --> D1 --> D2
  • Stored: at scrape time in S3 (raw-data-bucket).
  • Loaded for AI: during enrichment, after post fetch, at LangGraph run.
  • Missing image: vision nodes return skipped_no_image; text nodes still run.
  • TikTok: same key pattern assumed; confirm media exists before expecting visual coverage.

4. What AI extracts vs what APIs/UI use

AI invents nothing about engagement or URLs; those are copied from scraped rows.

flowchart TB
  CAP[/Caption text/]
  IMG[(S3 image)]
  CAP --> D{{description + language}}
  CAP --> K{{keywords}}
  CAP --> ST{{semiotic text}}
  CAP --> T{{themes + evidence}}
  CAP --> PF{{product focus + evidence}}
  IMG --> FV{{functional visual categories}}
  IMG --> SV{{semiotic visual scores}}
  T --> TH[/themes API\nBrand UI live/]
  PF --> PR[/products API\nBrand UI live/]
  ENG[(Engagement from scrape)] --> TC[/top-content API\nBrand UI live/]
  FV --> FVAPI[/functional-visual API\nlive / UI dummy/]
  SV --> SEM[/semiotic API\nlive / UI dummy/]
  REF[(image_ref on row)] --> GAL[/gallery API\nplanned/]
  • Grounding: theme/product evidence must be a verbatim caption substring.
  • Closed vocab (functional): product, ingredient, prepared_food, family, individual, in_home, out_of_home.
  • Closed vocab (semiotic visual): premium, healthy, natural, modern, traditional, sophisticated, indulgent.

5. Enrichment sequence - scrape data to saved analysis

sequenceDiagram
  autonumber
  actor Ops as Operator
  participant CLI as enrichment.run
  participant PG as Postgres public
  participant S3 as S3 media
  participant AG as LangGraph AI
  participant LLM as OpenAI
  participant FI as food_intel
  Ops->>CLI: run platforms + limit
  CLI->>PG: fetch brand posts
  PG-->>CLI: post rows
  loop Each post
    CLI->>FI: already enriched?
    CLI->>S3: HEAD media key
    alt Image found
      S3-->>CLI: image_ref
      CLI->>S3: create presigned URL
    else No image
      Note over AG: vision nodes skipped
    end
    CLI->>AG: analyze_post
    par Text nodes
      AG->>LLM: caption fields
      LLM-->>AG: description themes products
    and Vision nodes
      AG->>LLM: image fields
      LLM-->>AG: visual + semiotic scores
    end
    AG-->>CLI: analysis + node_status
    CLI->>FI: upsert analysis themes products
  end
  CLI-->>Ops: enrichment stats
